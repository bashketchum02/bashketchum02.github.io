# engineering is not about coding
Engineering for me, is not really about coding. A lot of what I do every day is about deciding what needs to be built, convincing people that it needs to be built, writing reports
& communicating them, helping people get unblocked & reading, lots of reading. Engineering is about understanding systems, how they interact with other systems. Coding is an implementation
detail, and I don't think coding is the most important part of a software engineer's career.

# coding as an art form
Now, coding as an art form, is a completely different conversation. I do think writing good and elegant code is an art form. It requires careful consideration, planning & most importantly, "taste"
to write good code. Not all handwritten code is good, or tasteful (and I don't claim that my code is any good either). Good code is not a strict prerequisite of good software, if that were the
case there would not have been that much good software, because most people are not good coders. Churning out thousands of lines of good tasteful code is hard for both humans and AI agents,
because just like art, coding requires deliberation, and being deliberate about millions of lines of code is simply too much overhead.

All products have two versions, cheaply mass produced ones that meet the growing demands of the masses & tastefully crafted artisan versions that enthusiasts care about. 
I see coding the same way — there are ~8 billion people on this planet, and demand only keeps growing.

The art of writing code has nothing to do with making good software, and everything to do with just liking the act of expressing your thoughts with code. I personally
still write code by hand for fun on weekends, but rarely for work. It's not the best use of my time to deeply think about the code I need to ship under time & monetary constraints, 
that is better suited for AI agents, because the volume, demand and urgency matters more than my personal taste. If I spent 5 days writing a piece of code because of taste, I will be
slowing everyone down. I don't have such constraints for personal projects, so I can hand write all the code I want.

# so what?
I realize, some things are hard to trust the agents with, because not all of engineering is about mass producing, some of it is about taste (especially: deciding what to build, and why, is taste).
As I lean more on agentic coding at work, I realize there is a real conflict within myself, sometimes I still feel the urge to understand every line of code and at the same time I want to keep moving fast. 
I am trying my best to actively classify "which parts of work need my attention?", "which parts of the work are better handled by AI agents?", and I am increasingly convinced that coding for profit is better
handled by AI agents. The agents get the volume, I keep the judgment.
